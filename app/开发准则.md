# 《烈焰除蟑：火线守卫》开发准则

**文档版本**：1.5.0  
**最后更新**：2026-07-23  
**适用范围**：所有后续功能开发

---

## 一、核心原则

> **引擎只做编排，不做实现。每个功能一个模块，每个模块一个文件。**

`engine.ts` 的角色是**调度中心**（Orchestrator），不是**万能口袋**（God Object）。它的职责仅限于：

1. 实例化各功能模块
2. 在主循环中按顺序调用模块的 `update()` / `render()` 方法
3. 处理模块通过回调上报的副作用（粒子、音效、振动、UI 通知等）
4. 管理游戏状态机（MENU → PLAYING → PAUSED → GAME_OVER 等）

**禁止**在 `engine.ts` 中直接编写新功能的业务逻辑。

## 三、模块开发模式

### 模式 A：实例模块（有状态模块）

**适用场景**：需要维护自身状态的功能（计时器、冷却、阶段切换等）。

**模板结构**：

```typescript
/**
 * @fileoverview [功能名称]模块
 * @description [一句话描述模块职责]
 */

import { /* 需要的类型 */ } from '../../types';

// ========== Config 接口 ==========
/** 模块配置：从引擎读取的只读/可读数据 */
export interface XxxSystemConfig {
  /** 画布宽度 */
  canvasWidth: number;
  /** 防御线 Y 坐标（用 getter 函数保证实时性） */
  defenseLineY: () => number;
  // ... 其他配置
}

// ========== Callbacks 接口 ==========
/** 模块回调：向引擎上报副作用 */
export interface XxxSystemCallbacks {
  /** 添加浮动文字 */
  onAddFloatingText?: (x: number, y: number, text: string, color: string) => void;
  /** 播放音效 */
  onPlaySound?: (name: string) => void;
  /** 屏幕震动 */
  onScreenShake?: (amount: number) => void;
  /** 添加粒子 */
  onAddParticle?: (particle: any) => void;
  /** 更新经济 */
  onEconomyUpdate?: (economy: any) => void;
  /** 更新防线 */
  onDefenseUpdate?: (hp: number, maxHp: number) => void;
  // ... 其他回调
}

// ========== 模块类 ==========
export class XxxSystem {
  private config: XxxSystemConfig;
  private callbacks: XxxSystemCallbacks;

  constructor(config: XxxSystemConfig, callbacks: XxxSystemCallbacks) {
    this.config = config;
    this.callbacks = callbacks;
    // 初始化内部状态
  }

  /** 每帧更新 */
  update(dt: number, time: number): void {
    // 核心逻辑
  }

  /** 重置状态 */
  reset(): void {
    // 清理状态
  }
}
```

**在 engine.ts 中的集成方式**：

```typescript
// 1. 构造函数中实例化
this.xxxSystem = new XxxSystem(
  {
    canvasWidth: this.canvas.width,
    defenseLineY: () => this.defenseLineY,
  },
  {
    onAddFloatingText: (x, y, text, color) => { this.addFloatingText(x, y, text, color); },
    onPlaySound: (name) => { this.audio.play(name); },
    onScreenShake: (amount) => { this.screenShake = amount; },
  }
);

// 2. update() 主循环中调用
this.xxxSystem.update(this.dt, this.time);

// 3. resetGame() 中重置
this.xxxSystem.reset();
```

### 模式 B：静态渲染模块（无状态模块）

**适用场景**：纯渲染逻辑，不维护状态，通过参数接收所有数据。

**模板结构**：

```typescript
/**
 * @fileoverview [渲染功能名称]渲染模块
 * @description [一句话描述]
 */

// ========== Config 接口 ==========
export interface XxxRenderConfig {
  /** 需要渲染的数据 */
  data: SomeType[];
  /** 图片资源 */
  images: Record<string, HTMLImageElement>;
  /** 时间戳 */
  time: number;
  // ... 其他参数
}

// ========== 静态方法 ==========
export class XxxRenderer {
  /**
   * 渲染 [功能名称]
   * @param config - 渲染配置
   * @param ctx - 画布上下文
   */
  static render(config: XxxRenderConfig, ctx: CanvasRenderingContext2D): void {
    // 纯渲染逻辑，不修改任何状态
  }
}
```

**在 engine.ts 中的集成方式**：

```typescript
// render() 方法中直接调用静态方法
XxxRenderer.render(
  {
    data: this.xxxData,
    images: this.images,
    time: this.time,
  },
  this.ctx
);
```

## 四、开发流程

### 4.1 新功能开发步骤

```
步骤 1 ──→ 步骤 2 ──→ 步骤 3 ──→ 步骤 4 ──→ 步骤 5 ──→ 步骤 6
分析需求   创建模块   定义接口   实现逻辑   集成到引擎  验证
```

| 步骤 | 操作 | 产出 |
|:---:|------|------|
| 1 | **分析需求**：确定功能属于哪种模块类型（实例 / 静态） | 设计决策 |
| 2 | **创建模块文件**：在 `engine/` 下创建子目录和文件 | `engine/xxx/XxxSystem.ts` |
| 3 | **定义接口**：Config 接口（入参）+ Callbacks 接口（出参） | 两个 interface |
| 4 | **实现逻辑**：编写模块核心代码，通过 `this.callbacks` 上报副作用 | 完整模块代码 |
| 5 | **集成到引擎**：在 `engine.ts` 构造函数中实例化，在 `update()`/`render()` 中调用 | 3 处引擎修改 |
| 6 | **验证**：`npx tsc --noEmit` + `npx vite build` 必须通过 | 编译 + 构建成功 |

### 4.2 引擎修改清单

每次新增模块，只需在 `engine.ts` 中修改 **3 个位置**：

| 位置 | 操作 | 代码量 |
|------|------|:---:|
| 构造函数 | `new XxxSystem(config, callbacks)` | ~15 行 |
| `update()` | `this.xxxSystem.update(dt, time)` | 1 行 |
| `resetGame()` | `this.xxxSystem.reset()` | 1 行 |

如果是静态渲染模块，只需在 `render()` 中加 1 行调用。

## 五、回调接口规范

### 5.1 标准回调命名

所有回调统一使用 `on` 前缀，动词后置：

```typescript
// ✅ 正确
onAddFloatingText    // 添加浮动文字
onPlaySound          // 播放音效
onScreenShake        // 屏幕震动
onEconomyUpdate      // 更新经济
onDefenseUpdate      // 更新防线
onPlayerUpdate       // 更新玩家
onStateChange        // 切换状态
onSpawnParticle      // 生成粒子

// ❌ 错误
addFloatingText      // 缺少 on 前缀
handleFloatingText   // 不明确
onFloatingTextAdd    // 动词后置不符合习惯
```

### 5.2 回调设计原则

1. **回调必须可选**（`?:`）：模块不应假设回调一定存在，调用前检查 `this.callbacks.xxx?.()`
2. **回调不应包含业务逻辑**：回调只负责通知引擎，具体处理由引擎完成
3. **避免回调地狱**：每个模块的回调数量控制在 5-15 个以内
4. **箭头函数包装**：在引擎中注入回调时，如需访问运行时状态，必须用箭头函数包装

```typescript
// ✅ 正确：箭头函数包装，运行时动态读取
onGetRoaches: () => this.roaches

// ❌ 错误：直接引用，捕获构造时的值
onGetRoaches: this.roaches
```

### 5.3 数据传递方向

```
引擎 ──Config接口──→ 模块（读取数据）
引擎 ←──Callbacks── 模块（上报副作用）
```

- **Config**：引擎 → 模块，传递模块需要读取的数据
- **Callbacks**：模块 → 引擎，模块通知引擎执行副作用

## 六、代码规范

### 6.1 文件组织

```
engine/xxx/
├── XxxSystem.ts        # 实例模块（有状态逻辑）
└── XxxRenderer.ts      # 静态渲染模块（如有渲染需求）
```

### 6.2 注释规范

每个模块文件必须包含：

```typescript
/**
 * @fileoverview [功能名称]模块
 * @description [一句话描述模块职责]
 */
```

每个公开方法必须包含 JSDoc：

```typescript
/**
 * 更新风扇状态：递减计时器、更新叶片角度、对范围内蟑螂施加减速/击退
 * @param dt - 帧间隔时间（秒）
 * @param roaches - 当前所有蟑螂列表
 */
update(dt: number, roaches: Roach[]): void { ... }
```

### 6.3 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 模块类 | `XxxSystem`（实例）/ `XxxRenderer`（静态） | `FanSystem`、`RoachRenderer` |
| Config 接口 | `XxxSystemConfig` / `XxxRenderConfig` | `FanSystemConfig` |
| Callbacks 接口 | `XxxSystemCallbacks` | `BossBattleCallbacks` |
| 私有属性 | `private` 前缀 | `private config: FanSystemConfig` |
| 回调方法 | `on` + 动词 + 名词 | `onAddFloatingText` |

## 七、反面案例

### ❌ 错误做法：直接在 engine.ts 中写功能

```typescript
// ❌ 不要这样做！
update() {
  // 直接在 engine.ts 中写风扇逻辑
  if (this.fanActive) {
    this.fanTimer -= dt;
    if (this.fanTimer <= 0) {
      this.fanActive = false;
      this.fanTimer = 0;
    }
    // 风扇效果：减速蟑螂
    for (const roach of this.roaches) {
      if (roach.x > fanX - fanRadius && roach.x < fanX + fanRadius) {
        roach.speed *= 0.5;
      }
    }
  }
  // ... 更多功能直接堆在这里
}
```

**问题**：`engine.ts` 会不断膨胀，最终回到 9700 行的噩梦。

### ✅ 正确做法：提取为独立模块

```typescript
// ✅ engine.ts 中只需一行
this.fanSystem.update(dt, this.roaches);

// ✅ 所有逻辑在 FanSystem.ts 中
```

## 八、代码审查清单

提交代码前，逐项检查：

- [ ] 新功能代码在独立模块文件中，不在 `engine.ts` 中
- [ ] 模块通过 Config 接口接收数据，通过 Callbacks 接口上报副作用
- [ ] 所有回调使用 `?.()` 可选调用，防止空引用
- [ ] 引擎中注入回调时使用箭头函数包装（如需要运行时状态）
- [ ] 模块提供 `reset()` 方法（如有状态），并在 `engine.ts` 的 `resetGame()` 中调用
- [ ] `reset()` 方法仅重置单局数据，不重置持久化数据（如成就解锁状态、天赋进度等）
- [ ] `updateConfig()` 方法支持动态更新配置（如需要）
- [ ] 所有公开方法有 JSDoc 注释
- [ ] `index.ts` 中导出新模块
- [ ] `npx tsc --noEmit` 零错误
- [ ] `npx vite build` 构建成功
- [ ] 更新 `引擎迁移.md` 变更记录

## 十、数值系统调用规则

> **核心原则：关卡内金币与总金币分离，所有奖励通过 `pendingRewards` 流转，仅在胜利时结算。**

### 10.1 金币体系架构

```
                    关卡内获得（HUD 实时显示）
                    ═══════════════════════════
    击杀蟑螂 ──→ pendingRewards ──→ GameHUD 显示 ¥{pendingRewards}
    成就奖励 ──→ onAddPendingReward()
    其他奖励 ──→ onAddPendingReward()
                    │
                    │ 关卡胜利时（gameVictory）
                    ▼
              victoryGoldReward ──→ 结算界面动画 ──→ settleVictoryGold()
                    │                                      │
                    │                                      ▼
                    │                              economy.money（总金币池）
                    │                              totalMoneyEarned（累计获得）
                    │
                    │ 关卡失败/退出
                    ▼
              pendingRewards = 0（金币不发放）
              economy.money 保持不变（已有金币池保留）
```

### 10.2 关键属性

| 属性 | 位置 | 类型 | 说明 |
|------|------|:---:|------|
| `pendingRewards` | `engine.ts` | `number` | 关卡内累计金币，HUD 实时显示，初始 0 |
| `victoryGoldReward` | `engine.ts` | `number` | 胜利时从 `pendingRewards` 拷贝，供结算界面动画展示 |
| `economy.money` | `Economy` 接口 | `number` | 总金币池（跨关卡持久化），初始值 = `menuShopMoney` |
| `economy.totalMoneyEarned` | `Economy` 接口 | `number` | 累计获得金币（含已花费），用于成就统计 |
| `menuShopMoney` | `GameCanvas.tsx` | `number` | React 状态，持久化到 `localStorage`，商店扣款用 |

### 10.3 模块中如何添加金币奖励

**✅ 正确做法：使用 `onAddPendingReward` 回调**

```typescript
// 在模块的 Callbacks 接口中定义
export interface XxxSystemCallbacks {
  /** 添加关卡内待结算金币 */
  onAddPendingReward?: (amount: number) => void;
}

// 在模块中调用
this.callbacks.onAddPendingReward?.(reward);
```

**在 engine.ts 中绑定回调**：

```typescript
this.xxxSystem = new XxxSystem(config, {
  onAddPendingReward: (amount) => { 
    this.pendingRewards += amount; 
    this.onPendingRewardUpdate?.(this.pendingRewards); 
  },
});
```

**❌ 错误做法：直接修改 `economy.money`**

```typescript
// ❌ 绕过 pendingRewards，关卡内金币不会显示在 HUD 上
// ❌ 失败时金币不会清零
this.config.onAddMoney?.(amount);
this.economy.money += amount;
```

### 10.4 金币结算流程

| 时机 | 触发 | 行为 |
|------|------|------|
| 关卡胜利 | `gameVictory()` → `settleVictoryGold()` | `pendingRewards` → `victoryGoldReward` → 结算界面动画 → `economy.money += victoryGoldReward` |
| 关卡失败 | `gameDefeat()` / `checkDefense()` | `pendingRewards = 0`，`economy.money` 保持不变（已有金币池保留） |
| 暂停退出 | `handleQuit()` | 同步 `engine.economy.money` 到 `menuShopMoney`（保留已有金币） |
| 新游戏/重新开始 | `resetGame()` | `pendingRewards = 0`，`victoryGoldReward = 0` |
| 购买消耗品 | `ConsumableSystem` | 扣减 `economy.money`（总金币池），不影响 `pendingRewards` |

### 10.5 引用同步检查清单

当 `resetGame()` 中创建新对象时，必须检查所有持有该对象引用的子系统：

```typescript
// engine.ts - resetGame()
this.economy = this.createEconomy(initialMoney); // ① 创建新对象
this.roaches = [];
this.placedBombs = [];
this.deadTimedBombs = [];

// ② 必须同步到所有持有引用的子系统！
this.roachAISystem?.updateConfig({
  economy: this.economy,       // ← 必须同步
  player: this.player,         // ← 必须同步
  roaches: this.roaches,       // ← 必须同步
  placedBombs: this.placedBombs,     // ← 必须同步
  deadTimedBombs: this.deadTimedBombs, // ← 必须同步
});
```

**检查项**：
- [ ] `resetGame()` 中创建的新数组/对象是否已同步到所有持有引用的子系统
- [ ] 使用 getter 函数（`getEconomy: () => this.economy`）的子系统不受影响
- [ ] 使用固定引用（`economy: this.economy`）的子系统必须通过 `updateConfig()` 同步

### 10.6 经济数值的来源

所有游戏内经济数值必须通过 `EconomyManager` 统一计算，禁止在模块中硬编码：

| 数值类型 | 获取方式 | 示例 |
|---------|---------|------|

## 十一、浮动文字调用规则

> **核心原则：所有浮动文字内容、颜色、字体、大小必须集中管理，禁止硬编码。**

### 11.1 浮动文字架构

```

    │

engine.ts → FloatingTextSystem.addFloatingText()

    │ 存储到 floatingTexts[]

    ▼

    │
    ▼
```

## 十二、音效系统调用规则

> **核心原则：AudioManager 统一管理所有音效，通过 Web Audio API 合成 + HTMLAudioElement 播放两种方式实现。**

### 12.1 音效系统架构

```
游戏逻辑层（模块/引擎）
    │
    │ 调用 this.audio.xxx()
    ▼
AudioManager（audio.ts）
    ├── HTMLAudioElement（文件音效）
    │   ├── BGM: bgm, gameOverBgm, victoryBgm
    │   ├── SFX: fireSfx, killSfx, swatterSfx, reloadSfx, clickSfx
    │   └── 一次性: nurse_cast.mp3, mutant_transform.mp3, flying_dodge.mp3
    │
    └── Web Audio API（合成音效）
        ├── 短促音效: playCoinTick, playCountdownTick, playBreachSound, playDanmaku
        ├── 琶音序列: playItemDrop, playItemDropFanfare, playStickySpray
        ├── Boss 音效: playBossCharge, playBossChargeHit
        └── 循环音效: startFanLoop/stopFanLoop, startFireWallBurn/stopFireWallBurn, startFlyingBuzzLoop/stopFlyingBuzzLoop
```

### 12.2 BGM 管理规则

**BGM 生命周期**：切换 → 播放 → 停止，三者严格分离。

```
场景切换时              战斗开始时              游戏结束时
switchBGMForScene() → startLevelBGM() → stopBGM()
（不播放）              （播放）                （停止）
```

| 方法 | 调用时机 | 说明 |
|------|------|------|
| `switchBGMForScene(scene, difficulty)` | 关卡开始前（`start()` 之前） | 根据场景/难度选择 BGM 路径，调用 `switchBGM()` 创建新 Audio 元素，**不播放** |
| `startLevelBGM()` | 3-2-1 倒计时结束后 | 播放当前 BGM |
| `stopBGM()` | 关卡结束/失败/退出 | pause + currentTime = 0 |
| `pauseBGM()` / `resumeBGM()` | 暂停/恢复 | 暂停菜单 |
| `fadeOutBGM(targetVol, duration)` | Boss 战/商店场景 | 渐变淡出到指定音量 |
| `playGameOverBGM()` | 防线被突破 | 每次重新创建 Audio 元素确保可靠播放 |
| `stopGameOverBGM()` | 退出结算界面 | 停止并清理 |
| `playVictoryBGM()` | 关卡胜利 | 播放胜利 BGM |
| `stopVictoryBGM()` | 退出胜利界面 | 停止胜利 BGM |

**关键约束**：

1. **创建顺序**：`new Audio()` → 设置 `preload = 'auto'` → 设置 `src`（不可颠倒）
2. **切换前必须先停止旧 BGM**：`pause()` → `currentTime = 0` → `removeAttribute('src')`（不要用 `load()` 避免触发 error 事件）
3. **`switchBGM()` 必须设置 `muted`**：`this.bgm.muted = this.isMuted`（不能硬编码 `false`）
4. **`play()` 必须处理 `AbortError`**：这是 `pause()` 打断 `play()` 的正常竞态，静默忽略
5. **主菜单无 BGM**：BGM 仅在关卡战斗期间播放（3-2-1 倒计时后）

### 12.3 SFX 播放规则

**文件音效**（HTMLAudioElement）：火焰、击杀、电蚊拍、换弹、点击

| 方法 | 说明 | 特殊处理 |
|------|------|------|
| `playFire()` / `stopFire()` | 火焰喷射（循环） | loop = true |
| `playKill()` | 击杀蟑螂 | 每次 `currentTime = 0` 重置 |
| `playClick()` | UI 点击 | 受 `suppressClickSfx` 控制（游戏中屏蔽） |
| `playReload()` | 换弹/换罐 | 每次 `currentTime = 0` 重置 |

**合成音效**（Web Audio API）：所有短促音效通过 OscillatorNode + GainNode 合成，无需音频文件。

| `playBreachSound()` | 300ms | 防线突破蜂鸣警告 |

| `playBossCharge()` | 500ms | Boss 冲锋蓄力隆隆声 |
| `playBossChargeHit()` | 400ms | Boss 撞击重击 |
| `playSuicideExplode()` | 3.6s | 自爆蟑螂爆炸（深沉咚 + 混响尾音） |
| `playTimedBombDrop()` | 300ms | 定时炸弹放置（机械咔哒） |

```typescript
playCoinTick() {

    // ...
}

// ✅ 正确：BGM 播放时也检查
startBGM() {
    if (this.bgm && !this.isMuted && !this.bgm.muted) {
        this.bgm.play().catch(() => {});
    }
}
```

**`setupAudioUnmute` 回调**：用户首次交互时取消静音，但必须检查 `isMuted` 状态——如果用户已通过 UI 手动开启静音，则跳过取消静音。

4. **静音检查**：方法开头必须 `if (this.isMuted) return;`
5. **引擎调用**：在 `engine.ts` 中通过 `this.audio.xxx()` 调用
6. **循环音效**：必须在 `stop()` / `gameDefeat()` / `gameVictory()` 中停止

## 十三、React UI 组件与引擎通信规则

> **核心原则：引擎通过回调通知 React 状态变更，React 通过 ref 调用引擎方法，数据单向流动。**

### 13.1 通信架构

```
┌─────────────────────────────────────────────────┐
│  GameCanvas.tsx（桥接组件）                       │
│                                                  │
│  engineRef = useRef<GameEngine>()                │
│  ┌──────────────┐       ┌──────────────────────┐ │
│  │ engine.ts    │ 回调   │ React State          │ │
│  │              │──────→│ economy, player,      │ │
│  │ onEconomyUpd.│       │ pendingRewards,       │ │
│  │ onPendingRew.│       │ wave, defenseHp, ...  │ │
│  │ onStateChange│       └──────────┬───────────┘ │
│  │ ...          │                  │ props       │
│  └──────────────┘       ┌──────────▼───────────┐ │
│         ▲               │ 子组件                │ │
│         │ 方法调用       │ GameHUD              │ │
│         │               │ GameOverScreen       │ │
│  engineRef.current      │ PauseScreen          │ │
│  .start() / .stop()     │ ShopScreen           │ │
│  .restart() / .pause()  └──────────────────────┘ │
└─────────────────────────────────────────────────┘
```

### 13.2 核心状态同步模式

**引擎 → React 单向数据流**：

```typescript
// GameCanvas.tsx - 绑定回调
engine.onEconomyUpdate = (e: Economy) => setEconomy({ ...e });        // 展开新对象触发渲染
engine.onPendingRewardUpdate = (rewards: number) => setPendingRewards(rewards);
engine.onWaveUpdate = (w: number) => setWave(w);
engine.onDefenseUpdate = (hp: number, maxHp: number) => {
    setDefenseHp(hp);
    setMaxDefenseHp(maxHp);
};
engine.onStateChange = (state: GameState) => setGameState(state);
```

**关键原则**：
- 对象类型状态必须展开（`{ ...e }`）创建新引用，否则 React 不会重新渲染
- 引擎回调中不要做复杂计算，只做 `setState`
- 使用 `useCallback` 包装传递给子组件的回调，避免不必要的重渲染

### 13.3 GameOverScreen 结算界面

**Props 接口**：

| Prop | 类型 | 说明 |
|------|------|------|
| `economy` | `Economy` | 引擎经济状态（包含 `money` 总金币池） |
| `isVictory` | `boolean` | 胜利/失败 |
| `victoryGoldReward` | `number` | 关卡内获得的金币（用于动画展示） |
| `onSettleGold` | `() => void` | 动画完成后回调 → 调用 `engine.settleVictoryGold()` |
| `menuMoney` | `number` | 跨关卡总金币（`menuShopMoney`），失败时显示 |
| `audio` | `AudioManager` | 音效管理器（用于动画音效） |

**金币动画实现规则**：

```typescript
// 动态时长：基础 1000ms + 每金币 3ms，最低 800ms，最高 5000ms
const duration = Math.max(800, Math.min(1000 + reward * 3, 5000));
const tickInterval = 50; // 固定 50ms 间隔，音效保持固定节奏
const steps = Math.round(duration / tickInterval);

// 每步更新 displayGold + 播放音效
setDisplayGold(newGold);
audio?.playCoinTick();
```

**结算流程**：

```
胜利: gameVictory() → pendingRewards → victoryGoldReward
      → GameOverScreen 金币动画（1-5s，动态时长）
      → onSettleGold() → engine.settleVictoryGold()
      → economy.money += victoryGoldReward

失败: gameDefeat() → pendingRewards = 0
      → GameOverScreen 显示 economy.money（已有金币池保留）
      → menuMoney 同步（handleQuit 时）
```

### 13.4 GameHUD 关卡内 HUD

**关键状态**：

| 状态 | 来源 | 显示内容 |
|------|------|------|
| `pendingRewards` | `engine.onPendingRewardUpdate` | 关卡内金币 ¥{N} |
| `economy.money` | `engine.onEconomyUpdate` | 总金币池（商店扣款用） |
| `wave` | `engine.onWaveUpdate` | 当前波次 |
| `defenseHp / maxDefenseHp` | `engine.onDefenseUpdate` | 防线血量 |

**注意**：HUD 金币显示使用 `pendingRewards`（关卡内），不是 `economy.money`（总金币池）。

### 13.5 退出/重启流程

```typescript
// handleQuit: 暂停退出 → 同步 economy.money → 停止引擎
const handleQuit = useCallback(() => {
    engineRef.current?.audio.stopBGM();
    engineRef.current?.saveProgress();
    setMenuShopMoney(engine.economy.money);  // 同步总金币池
    localStorage.setItem('roach_blaster_menu_money', String(engine.economy.money));
    engineRef.current?.stop();
}, []);

// handleRestart: 重新开始 → 停止音频 → 引擎重启 → 切换 BGM → 引擎启动
const handleRestart = useCallback(() => {
    engineRef.current?.audio.stopBGM();
    engineRef.current?.audio.stopVictoryBGM();
    engineRef.current?.audio.stopGameOverBGM();
    engineRef.current?.restart();
    // 必须在 restart() 的 stop() 之后、start() 之前切换 BGM
    engine.audio.switchBGMForScene(engine.currentScene, engine.difficulty);
    engine.start(gameMode, currentScene, true);
}, []);
```

## 十四、localStorage 持久化规则

> **核心原则：跨关卡金币通过 `menuShopMoney` 持久化，存档通过 `SaveSystem` 管理，两者互不干扰。**

### 14.1 持久化架构

```
localStorage
├── roach_blaster_menu_money    → 跨关卡总金币（menuShopMoney）
├── roach_blaster_endless_best  → 无尽模式最佳成绩
└── roach_blaster_progress      → 游戏存档（SaveSystem 管理）
```

### 14.2 menuShopMoney 读写规则

| 操作 | 时机 | 代码 |
|------|------|------|
| **读取** | 组件挂载时 | `localStorage.getItem('roach_blaster_menu_money')` |
| **写入** | 关卡胜利结算后 | `settleVictoryGold()` 完成后 |
| **写入** | 暂停退出 | `handleQuit()` 中 |
| **写入** | 商店购买后 | 购买消耗品/天赋后 |
| **不写入** | 关卡失败 | 保持原值不变（金币池未变） |

```typescript
// ✅ 正确：同步写入
```

## 十五、道具/库存系统规则

> **核心原则：道具库存修改必须创建新数组引用，删除后必须通知 UI 更新，确保 React 状态正确同步。**

### 15.1 库存数据流

```
拾取道具 ──→ inventory.push(item) ──→ onInventoryUpdate(inventory) ──→ React setState
    │
使用道具 ──→ 数量递减 ──→ 数量为 0 时 filter 移除 ──→ onInventoryUpdate(inventory)
    │
    ▼
React 重新渲染道具栏图标
```

### 15.2 数组不可变原则

**React 状态更新依赖引用变化**，必须创建新数组而非修改原数组：

```typescript
// ✅ 正确：使用 filter 创建新数组引用
this.inventory = this.inventory.filter(item => item.count > 0);
this.callbacks.onInventoryUpdate?.(this.inventory);

// ❌ 错误：splice 就地修改，数组引用不变，React 不重新渲染
const index = this.inventory.findIndex(item => item.count === 0);
this.inventory.splice(index, 1);
this.callbacks.onInventoryUpdate?.(this.inventory); // React 检测不到变化！
```

### 15.3 onItemRelease 规范

当道具用完（数量归零）时，`onItemRelease()` 方法必须：

1. 使用 `filter` 创建新数组（移除 count === 0 的道具）
2. 调用 `this.callbacks.onInventoryUpdate?.(this.inventory)` 通知 UI

```typescript
// ✅ 正确：完整的道具释放流程
onItemRelease(itemType: ItemType): void {
    // 1. 从库存中移除
    this.inventory = this.inventory.filter(item => item.type !== itemType || item.count > 0);
    // 2. 通知 UI 更新
    this.callbacks.onInventoryUpdate?.(this.inventory);
}
```

### 15.4 道具栏图标消失规则

- 道具使用完最后一个后，图标必须从拾取道具栏消失
- 根因检查清单：`filter` vs `splice` | `onItemRelease` 是否调用 `onInventoryUpdate` | 新数组引用是否正确赋值

### 15.5 引擎侧集成

```typescript
// engine.ts - 绑定库存回调
this.consumableSystem = new ConsumableSystem(config, {
    onInventoryUpdate: (inventory) => {
        this.inventory = inventory;                // 同步引擎库存
        this.onInventoryUpdate?.(inventory);       // 通知 React UI
    },
});
```

## 十六、模块迁移与重构验证规则

> **核心原则：每次模块迁移后，必须验证视觉方向、伤害区域、回调闭包等关键行为与原实现一致。**

### 16.1 迁移后验证清单

| 验证项 | 说明 | 历史案例 |
|--------|------|------|
| **视觉方向** | 确认渲染方向与原始代码一致 | `RadarLaser` 激光方向从 bottom→up 反转为 top→down |
| **伤害区域** | 确认伤害判定范围与视觉效果一致 | `InsecticideSystem` 伤害区域与锥形渲染不匹配 |
| **回调闭包** | 确认箭头函数包装正确，无 undefined 引用 | `ConsumableSystem` 回调引用旧 `economy` 导致金币不更新 |
| **状态同步** | 确认 `resetGame()` 后所有子系统引用已更新 | 见 10.5 引用同步检查清单 |

### 16.2 回调闭包陷阱

模块回调中访问的引擎状态必须通过箭头函数或 getter 动态获取，不能捕获构造时的值：

```typescript
// ✅ 正确：箭头函数在调用时动态读取
this.xxxSystem = new XxxSystem(config, {
    onGetEconomy: () => this.economy,       // 始终获取最新引用
    onGetRoaches: () => this.roaches,       // 始终获取最新引用
});

// ❌ 错误：直接引用，捕获构造时的值，resetGame() 后失效
this.xxxSystem = new XxxSystem(config, {
    economy: this.economy,                   // 永远指向旧对象
    roaches: this.roaches,                   // 永远指向旧数组
});
```

### 16.3 迁移标准流程

```
步骤 1 ──→ 步骤 2 ──→ 步骤 3 ──→ 步骤 4 ──→ 步骤 5
创建模块   集成引擎   替换调用   清理旧代码  验证
```

| 步骤 | 操作 | 产出 |
|:---:|------|------|
| 1 | 创建模块文件，实现完整逻辑 | `XxxSystem.ts` |
| 2 | 在 engine.ts 构造函数中实例化，注入回调 | 构造函数 + update() + reset() |
| 3 | 将所有对旧方法/属性的调用替换为模块委托 | 无遗留旧代码引用 |
| 4 | 删除 engine.ts 中的旧属性、旧方法 | 清理冗余代码 |
| 5 | `npx tsc --noEmit` + `npx vite build` 必须通过 | 编译 + 构建成功 |

### 16.4 迭代验证

每完成一个模块的迁移就立即验证，不要批量迁移后统一验证——问题定位困难。

## 十八、tRPC 云存档规则

> **核心原则：开发模式下没有后端服务，tRPC API 调用会返回 500 错误，必须静默抑制，不能影响游戏正常运行。**

### 18.1 错误抑制

```typescript
// ✅ 正确：包装 fetch，开发模式 500 错误静默返回空响应
async function cloudSave(data: SaveData): Promise<void> {
    try {
        const response = await fetch('/api/trpc/save', {
            method: 'POST',
            body: JSON.stringify(data),
        });
        if (!response.ok) {
            // 开发模式 500 错误静默忽略
            console.warn('[CloudSave] Server returned', response.status, '(dev mode, ignoring)');
            return;
        }
        return response.json();
    } catch (error) {
        // 网络错误也静默忽略
        console.warn('[CloudSave] Network error (dev mode, ignoring):', error);
    }
}
```

### 18.2 云存档设计原则

1. **本地优先**：本地 `localStorage` / `SaveSystem` 始终是主要数据源
2. **云存档异步**：云端保存为 fire-and-forget 模式，不阻塞游戏流程
3. **错误静默**：所有云端 API 错误必须静默处理，不影响游戏体验
4. **开发模式容错**：`fetch` 调用必须包装 try-catch，500 错误视为正常

## 十九、成就解锁动画规则

> **核心原则：成就解锁后通过 `newlyUnlockedIds` 追踪，打开成就界面时自动播放弹出动画，播放后标记清除，确保不重复播放。**

### 19.1 动画数据流

```
关卡内成就解锁 ──→ newlyUnlockedIds.add(ach.id) ──→ 累积到队列
                        │
            打开成就界面 ──→ getPendingAnimations()
                        │
                        ▼
              AchievementUnlockPopup 动画
              （樟树头像 + 气泡文字 + 粒子特效 + 音效）
                        │
                        ▼
              markAnimationPlayed(id) → 从队列移除
                        │
                        ▼
              队列为空 → 显示成就列表
                        │
            关闭成就界面 ──→ clearAnimationQueue()
                        │
            新游戏开始 ──→ reset() → newlyUnlockedIds.clear()
```

### 19.2 AchievementSystem 新增接口

| 方法 | 签名 | 调用时机 |
|------|------|------|
| `getPendingAnimations()` | `() => AchievementData[]` | 打开成就界面时，获取待播放动画的成就列表 |
| `markAnimationPlayed(id)` | `(id: string) => void` | 单个动画播放完成，从队列移除 |
| `clearAnimationQueue()` | `() => void` | 关闭成就界面时，清空所有动画标记 |

### 19.3 动画时序

| 时间 | 阶段 | 说明 |
|------|:---:|------|
| 0ms | 遮罩层淡入 + 头像从左侧弹入 | `opacity 0→1` + `translateX(-100%→0)`，弹性缓动 |
| 200ms | 气泡弹出 | `scale(0→1.1→1)`，0.3s |
| 400ms | 粒子爆发 | 12 个金色星星从气泡中心向外扩散 |
| 2000ms | 全部淡出 | 头像退回左侧，气泡缩小消失 |
| 2200ms | 检查下一个动画 | 队列为空则显示成就列表 |

### 19.4 音效集成

动画播放时调用 `audio.playAchievementUnlock()`：
- Web Audio API 合成 C5→E5→G5 上行琶音（三个音符逐次叠加，持续约 0.25s 每个）
- 叠加一层闪光音效（triangle 波，1200Hz→2400Hz 扫频，0.5-0.7s）

### 19.5 成就持久化规则

**关键约束**：`AchievementSystem.reset()` 仅重置单局数据（`newlyUnlockedIds` 动画队列 + `economyStats` 单局统计），**不得重置成就解锁状态**。成就解锁状态属于持久化数据，通过 `SaveSystem` 管理，在每局开始时应保留。

```typescript
// ✅ 正确：reset() 仅清理动画队列和单局统计
reset(): void {
    this.newlyUnlockedIds.clear();
    this.config.economyStats = { totalKills: 0, highestWave: 0, ... };
}

// ❌ 错误：reset() 重置所有成就为未解锁
reset(): void {
    for (const ach of this.config.playerProgress.achievements) {
        ach.unlocked = false;  // 销毁持久化成就进度！
    }
}
```

### 19.6 引擎侧集成

```typescript

    return this.achievementSystem?.getPendingAnimations() ?? [];
```
