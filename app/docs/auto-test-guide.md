# 自测脚本使用说明（auto-test.mjs）

## 一、作用

数值平衡自测工具：以**全真 UI 点击流程**自动通关全部 11 个关卡，采集战斗采样数据（trace），
量化"**喷火枪伤害 vs 关卡怪物难度**"的曲线匹配度，生成可视化研究报告。

典型用途：**调整数值（火枪 DPS、怪物血量、波次生成量等）后重跑一次，直观对比调整前后的曲线变化。**

## 二、功能

脚本启动浏览器后全程无人值守，每关自动完成：

| 环节 | 行为 |
|---|---|
| 登录/加载界面 | 自动点击"点击开始" |
| 模式选择 | 自动点"剧情模式" |
| 难度选择 | 自动点"简单"（`hard` 参数则点"困难"） |
| 选关 | 按场景显示名（恐怖厨房 / 阴暗下水道 …）点击关卡卡片 |
| 跳过引导 | 自动跳过漫画（跳过）、剧情对话、厨房新手引导（跳过引导）、地铁精英/斩螂教学对话 |
| 战前准备 | 自动按道具名共选 **3 个**可使用道具后点"开始战斗"（每个道具只点一次，避免切换按钮取消选中） |
| 战斗 | 自动瞄准最靠近防线的蟑螂开火；场上无怪自动停火省燃气；**燃气低于 20% 时自动使用"气罐补给"**（需从商店购买带入） |
| 使用掉落道具 | 场上有怪且库存非空时，每 ~3 秒自动使用库存第一个道具（即点即用型直接生效；放置型自动选目标位置→松手部署） |
| 战后奖励 | **自动拾取掉落道具**（等待落地后反复点击、叠加浮动偏移修正直到拾取成功），自动关闭道具揭示界面 |
| 结算 | 采集本关 trace 写盘 → **胜利时自动进"道具商店"购买"气罐补给"** → 点"返回主菜单" → 进入下一关循环 |

11 关全部结束后自动生成研究报告。

## 三、使用方式

### 前置条件

1. dev 服务器已启动并监听 **3000 端口**（`npm run dev`）
2. 本机安装 Chrome 或 Edge（脚本自动探测，优先 Chrome）

### 命令

> 说明：本脚本已合并原 `auto-report.mjs` 的全部功能，测试、重生成报告、清理数据统一由本脚本完成，`auto-report.mjs` 已删除。

```bash
# 完整 11 关（简单难度，有界面，可观察过程）
node auto-test.mjs

# 困难难度（难度参数位置无关，任意位置出现 hard 即判为困难）
node auto-test.mjs hard
node auto-test.mjs --headless hard

# 无头模式（无浏览器窗口，后台运行，速度快、防误关）
node auto-test.mjs --headless

# 只跑指定关卡（单关调试 / 冒烟测试）
node auto-test.mjs --only=subway

# 仅从现有 traces 重生成报告（不启动浏览器测试，读取各关最新 trace）
node auto-test.mjs --report

# 生成报告但不自动在浏览器中打开（配合 --report 或测试结束）
node auto-test.mjs --report --no-open

# 仅清空 traces 旧数据（新一轮测试前重置），不做其他操作
node auto-test.mjs --clear
```

### 参数说明

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| 难度 | `easy` / `hard` | `easy` | 对应游戏内"简单 / 困难"；位置无关，`hard` 出现在任意参数位均生效 |
| `--headless` | — | 有界面 | 无头模式，不弹浏览器窗口；不加则显示窗口便于观察 |
| `--only=<scene>` | 关卡 id | 全部 11 关 | 只跑某一关，如 `--only=kitchen` |
| `--report` | — | 关闭 | 仅重生成报告：读取 traces 中各关最新数据生成 `auto-report.html`，不启动浏览器测试 |
| `--no-open` | — | 自动打开 | 生成报告后不自动在浏览器中打开（常与 `--report` 连用） |
| `--clear` | — | 关闭 | 仅清空 traces 目录中所有 trace 文件，立即退出，不测试不生成报告 |

关卡 id 列表（按解锁顺序）：
`kitchen` 厨房 → `sewer` 下水道 → `dump` 垃圾场 → `basement` 地下室 → `street` 街道 → `rooftop` 天台 → `hospital` 医院 → `subway` 地铁 → `supermarket` 超市 → `school` 学校 → `nest` 巢穴

可用 `GAME_URL` 环境变量覆盖游戏地址（默认 `http://localhost:3000`）。

### 典型组合场景

| 场景 | 命令 |
|---|---|
| 新一轮完整测试（先清旧数据 → 无头跑 11 关 → 自动出报告） | `node auto-test.mjs --clear` 后再 `node auto-test.mjs --headless` |
| 只重新生成报告并打开（不改数值，快速复盘已有 traces） | `node auto-test.mjs --report` |
| 生成报告但不弹窗（CI/脚本集成） | `node auto-test.mjs --report --no-open` |
| 观察单关战斗过程 | `node auto-test.mjs --only=subway`（不加 `--headless`） |

## 四、产物

### 1. `traces/roach-trace-<关卡>-<结果>-<时间戳>.json`

每关一份战斗采样（0.5s 间隔），字段：`t` 时间、`hp`/`armor`/`shield` 在屏怪物血量/护甲/护盾、
`flameDmg` 火焰累计输出、`spawnHp` 生成累计、`wave` 波次、`firing` 是否开火等。

### 1.5. `config-totals.json`（配置总强度曲线数据）

从数值配置解析计算的每关怪物总强度（血量/护甲/护盾/加血/加护甲/合计），供 `--report` 重生成报告复用。
口径同 `spawnRoach`（血量×难度系数，护甲/护盾取生成固定值）；加血/加护甲为"单次施放潜力"估计。

### 2. `auto-report.html`（研究报告，浏览器打开）

- **当前喷火枪数值配置表** —— 页面开头展示火枪各项数值（总 DPS、束/火区 DPS、射程、宽度、燃气、过热阈值、喷嘴偏移等），便于对照报告结果核对当前数值
- **一、11 关汇总表** —— 结果 / 时长 / 波次 / 生成总量 / 火焰输出 / 输出生成比 / 峰值在屏 / 交战 DPS / 开火占比 / 非火焰掉血
- **二、配置难度曲线 vs 喷火枪 DPS（同图双轴）** —— 怪物总强度（读取配置：HP+护甲+护盾+加血+加护甲，左轴）与喷火枪实测交战 DPS（右轴）画在同一张图；附每关配置总强度明细表
- **三、难度曲线 vs 喷火枪输出曲线** —— 火焰输出曲线贴合生成总量曲线 = 数值匹配；被反超的关卡 = 需要调整的节点
- **四、交战 DPS 曲线** —— 越平稳手感越一致，陡降即数值断点
- **五、逐关时序图** —— 在屏压力（红面积）vs 火焰累计输出（绿线）vs 生成累计（虚线）
- **六、自动结论** —— 自动列出未通关关卡、火力不足关卡、DPS 断点

### 3. 控制台汇总表

运行结束时打印与报告同口径的 11 关汇总。

## 五、指标口径

| 指标 | 含义 | 判读 |
|---|---|---|
| 生成总量 | 全关怪物 HP+护甲 流入（关卡难度） | 失败关只是败北时已生成量，偏小 |
| 火焰输出 | 喷火枪实际造成的总伤害 | 含束伤害+火区伤害 |
| 输出/生成 | 火焰输出 ÷ 生成总量 | ≥1 绿（火枪可独立清场）；0.7~1 黄（需道具兜底）；<0.7 红（火力不足）。**失败关该比率虚高，不代表火力充足** |
| 峰值在屏 | 同时存活的怪物 HP+护甲 峰值 | 持续走高 = 清怪速度跟不上生成 |
| 交战 DPS | 在屏有怪时段的火焰输出速率 | 关卡间对比火枪真实命中水平 |
| 开火占比 | 开火时间占比 | 过低说明长时间无怪可打 |
| 非火焰掉血 | ≈ 突破防线/道具造成的血量消减 | 大值 = 防线被大量突破 |

## 六、运行机制与注意事项

1. **存档会被重置**：脚本启动时清空 localStorage 并写入"全关卡+全武器解锁"的测试存档（解锁全部武器是为覆盖战前准备界面 UI 路径）。请勿在保留个人进度的浏览器配置下运行——脚本使用独立临时配置目录（`%TEMP%/roach-auto-test-profile`），不影响日常浏览器。
2. **UI 导航基于可见文字匹配**（按钮文字来自 `TEXT_CONFIG`），改动 UI 文案后需同步更新脚本内的匹配字符串。
3. **单关超时 8 分钟**、UI 导航超时 90 秒；导航超时兜底为直接 `engine.start()` 进入战斗，保证流程不中断。
4. 运行结束阶段的浏览器退出报错（沙盒拦截 Chrome 访问系统文件）是**噪音，不影响产物**。
5. trace 采样在游戏失败时会通过 `exportTrace('defeat')` 兜底导出，因此失败关同样有完整数据。
